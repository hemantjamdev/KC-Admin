# Documentation Rules

- Update project documentation whenever architectural patterns, APIs, or rules change.
- Keep `README.md` accurate and up to date.
- Document architectural design decisions, non-obvious business logic, and complex workflows.
- Do not add comments that merely restate standard Dart/Flutter syntax.
- Document public API contracts when behavior is non-obvious.
- Document Firestore collection structures when collections are created.
- Clearly document breaking changes or migration steps in completion summaries.
- Use valid GitHub-flavored markdown with clear headings, code blocks, and lists.
